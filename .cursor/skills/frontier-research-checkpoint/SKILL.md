# 前沿研究检查点

## 何时触发

- 重大架构/协议/协作模式决策前，方案出现多个合理分叉，各有取舍，需要外部证据裁决。
- 同一问题反复卡壁（尝试 ≥2 次仍未解决，或长期停滞）。
- 用户明确要求参考最新论文/前沿研究。

**不适用**：常规 bugfix、局部实现细节、仓库内已有先例可直接复用的情况——先按 `modularity-dry` 规则搜仓库，再决定是否需要外部文献。

## 工作流

1. 把问题拆成 2-4 个正交子话题分别检索，不要只搜一个笼统关键词（例如"多 agent 协作"应拆成协议演进 / 编排范式 / 失败归因 / 基准评测）。
2. 用 `WebSearch` 按当前年份限定检索最新进展，优先：
   - 综述/survey（建立分类框架）
   - 最新基准/benchmark（拿量化证据，不只拿主张）
   - 协议/规范变更（如 MCP/A2A 等，若话题相关）
   - 生产实践文章（补充学术论文覆盖不到的落地细节）
3. 对每条来源摘录：结论、量化证据（数字/相关系数/百分比）、发表时间、来源链接。
4. 产出「文献 → 关键发现 → 对本项目的含义」三列表，而不是罗列摘要；每条必须能回答"这对设计意味着改哪个点"。
5. 与现有方案冲突的结论标注为「纠偏」，并说明证据强度是否足以推翻现状；证据不足时保留现状，记录为「观察项」而非直接推翻。
6. 把结果写回触发该次检索的产出物（plan 文件 / 决策记录 / ADR），不要只留在对话里；保留可点击引用链接，便于日后复核。

## 交付格式

| 文献 | 关键发现 | 对本项目的含义 |
|------|----------|------------------|
| ... | 量化结论 | 改哪个设计点 / 是否纠偏 |

已验证案例：`.cursor/plans/multi-agent_collab_scheme_fdec6e8d.plan.md` §0（六个主题分组的文献表，含协议演进、失败归因、记忆治理、编码协作基准、群聊发言决策）。

## 复核触发

方案落地后若再次卡壁，或经过较长时间未回顾，重复本流程，只检索"上次时间点之后"的新进展，避免重复劳动。
